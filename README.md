# Распределение секций — Drag & Drop расписание

Прототип рабочего экрана для распределения учебных секций по недельной сетке (Пн–Пт × слоты из mock-данных).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # unit-тесты бизнес-правил (vitest)
npm run build      # type-check + production build
```

Требуется Node 20+.

Параметры URL для демонстрации:

| URL | Что показывает |
| --- | --- |
| `?sections=300` | +300 сгенерированных секций (виртуализированный список) |
| `?fail=1` | первый запрос к mock API падает → экран ошибки с «Повторить» |
| `?delay=2000` | искусственная задержка mock API, мс |

## Стек

- **React 19 + TypeScript + Vite**
- **TanStack Query** — загрузка данных из mock API (loading / error / retry)
- **TanStack Store** — состояние занятий (с undo/redo и persistence) и UI-состояние (фильтры, выбор секции, открытый редактор)
- **TanStack Virtual** — виртуализированный список секций (сотни секций без просадок)
- **TanStack Form** — редактор занятия (преподаватель, аудитория, день, время)
- **Ant Design 6** (+ `@ant-design/icons`) — UI-компоненты: Input, Select, Segmented, Button, Tag, Progress, Modal, Form, Alert, Popconfirm, notification, Result, Spin, Empty; тема и русская локаль через `ConfigProvider`
- **dnd-kit** — Drag & Drop (pointer + keyboard sensors)

## Что умеет

**Обязательные сценарии**

1. **Секция → расписание.** Перетащите секцию на ячейку. Преподаватель берётся из секции; если он не назначен — выбирается первый свободный из `allowedTeacherIds`, и сразу открывается компактный редактор для подтверждения. Аудитория подбирается автоматически: свободная, вмещающая всех студентов, предпочтительного типа (`preferredRoomType`), с минимальным запасом мест (чтобы не занимать большие аудитории без нужды).
2. **Занятие → другой слот.** Во время перетаскивания в ячейке под курсором показывается «призрак» будущего занятия (с преподавателем и аудиторией), исходная ячейка помечена пунктиром.
3. **Невалидный Drop.** Как только начинается drag, вся сетка раскрашивается: зелёные ячейки — можно, штриховка — конфликт. В ячейке под курсором и в строке статуса над сеткой — текст причины. Проверяются: занятость преподавателя, занятость аудитории, вместимость, `teacherBlockedSlots`, наличие у секции занятия в этом слоте, а также «все занятия секции уже распределены» и «нет свободной подходящей аудитории». Drop на невалидную ячейку ничего не меняет и показывает тост с причиной. При конфликте аудитории подсказывается свободная альтернатива.
4. **Возврат в нераспределённые.** Во время перетаскивания занятия левая панель превращается в drop-зону «снять с расписания». Счётчики секции и общий прогресс обновляются сразу. Также удалить можно из редактора.

**Список секций:** код, предмет, студенты, преподаватель (или «не назначен»), значок компьютерного класса, `placed / required`, прогресс-бар, цветовая полоса статуса (не начата / частично / готова), чипы с уже занятыми слотами. Незавершённые — сверху. Полностью распределённые секции не перетаскиваются.

**Карточка занятия:** секция, предмет, преподаватель, аудитория, заполненность `студенты/места`; красная отметка, если занятие конфликтует. Клик (или Enter) — редактор: смена преподавателя, аудитории (с пометками «занята / мала», кнопка «Подобрать»), дня и времени. Ошибки и предупреждения считаются вживую, «Сохранить» заблокирована при конфликте.

**Bonus**

- Undo / Redo (кнопки, `⌘/Ctrl+Z`, `⌘/Ctrl+Shift+Z`), «Отменить» прямо в тосте после каждого действия
- Поиск по коду/предмету, фильтр по статусу (с счётчиками), по преподавателю и по аудитории. При выбранном преподавателе/аудитории сетка показывает, где он(а) свободны/недоступны, а чужие занятия приглушаются
- Подсветка допустимых и недопустимых слотов во время drag
- Автоматический подбор аудитории
- **Альтернатива Drag & Drop без мыши:** клик/Enter по секции включает режим выбора слота — в доступных ячейках появляется кнопка «＋ сюда» (быстро расставлять несколько занятий подряд, `Esc` — выход). Занятия можно переносить через редактор (день/время) или клавиатурным drag dnd-kit (Space — взять, стрелки, Space — отпустить)
- Сохранение состояния после refresh (localStorage; «Сбросить» возвращает исходные данные, и это тоже можно отменить)
- Mock API с задержкой, loading и error/retry состояниями
- Виртуализация списка секций, адаптивная раскладка (на узком экране панель над сеткой)

## Архитектура

```
src/
  domain/          чистая бизнес-логика, без React
    types.ts         типы (реэкспорт types.ts) + Issue, SlotRef, LessonDraft
    catalog.ts       справочники с O(1)-lookup (секции, преподаватели, аудитории, блокировки)
    lessonIndex.ts   индексы занятий: по слоту, по секции
    validation.ts    правила конфликтов, подбор аудитории, план drop'а
    progress.ts      статус распределения секции
    validation.test.ts
  api/             mock API + TanStack Query hook
  store/           TanStack Store: scheduleStore (занятия, история, persistence), uiStore
  dnd/             типы drag-элементов / drop-целей, связь DnD ↔ domain
  hooks/           контекст справочника, производная модель, хоткеи
  components/      Workspace (DnD-оркестрация), SectionsPanel, ScheduleGrid, GridCell,
                   LessonCard, SectionCard, LessonEditor, AppHeader;
                   notify.tsx — обёртка над antd notification для вызова из DnD-обработчиков
  theme.ts         токены темы antd
```

Ключевые решения:

- **Правила — в `domain/validation.ts`, а не в JSX.** UI задаёт вопрос «что будет, если X положить в слот Y?» — `planSectionDrop` / `planLessonMove` возвращают `DropPlan`: `ok` (готовый `LessonDraft` + предупреждения + нужно ли подтверждение), `invalid` (список `Issue` с кодом, severity и человекочитаемой причиной) или `same`. Тот же код используется для drag, для режима клика, для подсветки всей сетки и для редактора — поведение везде одинаковое. Правила покрыты unit-тестами.
- **Ошибки vs предупреждения.** `Issue.severity`: `error` блокирует действие, `warning` (например, лекционная аудитория для секции, которой нужен компьютерный класс) — только информирует. В mock-данных у CS101-01 24 студента, а единственный компьютерный класс на 18 мест — блокировать такое было бы неверно.
- **При старте drag план считается для всех 30 ячеек один раз** (индекс занятий по слоту делает каждую проверку O(занятий в слоте)), поэтому подсветка не пересчитывается на каждое движение мыши.
- **Единственное изменяемое доменное состояние — массив занятий.** Все изменения идут через `commit()` в `scheduleStore`, что даёт undo/redo и persistence без дополнительного кода в компонентах. Справочники неизменяемы и раздаются через контекст.
- **Перенос занятия сохраняет преподавателя и аудиторию**; если аудитория в новом слоте занята — drop запрещён (это одно из обязательных правил), но в причине предлагается свободная аудитория, которую можно выбрать в редакторе.
